# Requirements 3 · The stages, as configurations of the one primitive

Part of [requirements.md](../requirements.md), whose section *How to read* defines the fields [ours].
Each stage below is a set of values for the behaviours of [02-primitive.md](02-primitive.md), never
a loop of its own [§3] [ours]. The table states every value once; each requirement after it adds
what a value alone cannot say, and its test [ours].

## The default stage configuration

The values come from the paper where it gives them, and are our decisions where it does not; each
cell says which [Tab. 1] [App. A.2] [ours]. A value set by another task is named, never guessed:
N_seed, N_p and N_t are task 5's, and the configuration refuses to load without them (R-STG-13)
[ours]. The cells use R-PRIM-2's vocabulary; where a cell implies a mechanism, such as the meta
stage's downstream pass, task 3 may build the same behaviour another way (A-NOTE-1) [ours]. The
cross-cutting checks run at hook points declared by the kind of step, not by stage (R-INT-10):
after a code-producing step, the component-list and switch-scope checks, the harness's scoring,
then the specification filter; after a manuscript-producing step, compile, number provenance,
references, then method–code alignment [§4.2] [ours]. A_Coder is a composite stage of two rows, and
the tail is not a stage of Table 1; it is the last stage of the run's sequence (R-RUN-7) [ours].

## Failures after retries, per role

When an agent's step still fails after its retries (R-PRIM-10, R-OPS-7), the role that failed sets
the outcome, by default as below. Each line is data, names an outcome of R-PRIM-2's vocabulary and
then its effect, and none maps a failure to accept or `Good`; a stage that names a role with no line
fails to load [ours]. Failures of agent code in a harness job, faults of the harness, and outages of
outside systems are not on this table: the first is a released result, the other two suspend the
run (R-PRIM-10, R-RUN-8) [ours].

| Role | Outcome after its retries, then its effect |
|---|---|
| Limitation Extractor, Limitation Verifier | the run stopped, *error after retries* [ours] |
| Idea Generator, and the initial idea's agent if it has one | nothing passed on for that attempt, which counts toward M; the pool keeps what it has [ours] |
| Novelty Checker | the candidate accepted with its score unknown, sorted last (R-AGT-6) [ours] |
| Baseline Coding Agent | the run stopped before it starts: the task is not admitted [ours] |
| Subset and Full-Set Coding Agents, their Engineers, the Subset and Full-Set Critics | nothing passed on: the idea is `Bad`, with the reason *error* [ours] |
| A_Evolve | nothing passed on for the evolved idea: the round runs its seed alone; with no candidate left, the accepted items kept, as at the rounds' limit [ours] |
| Selector | the candidate accepted: the band's leader, the failure recorded [ours] |
| Ablation Planner | nothing passed on for the plans: the pass runs its control alone, and the critic reads the failure [ours] |
| Ablation Coding Agent, Rebuttal Coding Agent | an item dropped, after its one re-run by a fresh session, and listed with its reason [ours] |
| Ablation Critic | the current best kept: drafting with the current h_best, the export marked *attribution not established* [ours] |
| A_FullEng | nothing passed on: the refinement is discarded into its guard's failure branch [ours] |
| Result Comparison Agent | no outcome of its own: its reading is recorded as missing, and the rule decides alone (R-PRIM-6) [ours] |
| Initial Drafter | the run stopped, *error after retries* [ours] |
| Rebuttal Planner, Paper Enhancer, Peer Reviewer | the last candidate kept, flagged: the last manuscript passes on, as at the review stage's limit [ours] |
| Meta-Reviewer | the last candidate kept: the tail, the export marked unapproved [ours] |
| the tail's writer | the last candidate kept: the final-filled manuscript goes to the gates unrevised [ours] |
| an integrity check | as task 6's gates set it: a filter that fails counts as a discard, a manuscript check as a failed check (R-INT-4, R-INT-10) [ours] |

## The stages

### R-STG-1 · Finding limitations

- **Requirement.** The limitation stage runs with the LIM values: the Extractor's set is judged by the Verifier, expanded while the Verifier finds it insufficient, and passed on after at most 15 judged refinements, so 16 rounds of extraction, flagged if the limit was reached [§3.1] [App. A.2] [ours]. An empty set is an empty output, which fails closed (R-PRIM-10). The Verifier's criterion and the limitation record are task 3's (U-LIM-1) [ours].
- **Traces.** P-LIM-1 … 4 [§3.1]; P-CFG-1 [App. A.2]; P-ROSTER-1, P-ROSTER-2 [§3.1].
- **Why ours.** The paper does not say what passes on at the limit; the next paragraph works from the limitations found, so the set passes on (A-LIM-1) [§3.1] [ours].
- **Decides.** A-TOP-1, its cell A-LIM-1 [ours].
- **Depends on.** U-LIM-1, task 3 [ours].
- **Test.** Logic, in mock mode: a Verifier scripted as always insufficient gives 16 Extractor calls and 16 Verifier calls, and the 16th set passes on, flagged; scripted as sufficient at once, one call of each and no flag; an Extractor scripted to return an empty set is retried, then ends the run with *error after retries* [ours].

### R-STG-2 · Seed ideas

- **Requirement.** The seed stage runs with the SEED values. Every idea gets a novelty score from two retrieved papers, and no idea is dropped for low novelty: the score only ranks [§3.1] [App. A.2] [ours]. The Idea Generator reads G, the limitations and the scored pool so far, under a written content rule that excludes pure compute or budget scaling; the rule is a prompt, and the guard against compute scaling is R-RUN-6's guardrail [§3.1] [App. B] [ours]. A generated idea that a written duplicate rule finds equal to one already in the pool is not added, and generation stops after M = 3 × N_seed attempts, with the reason recorded [ours]. N_seed is task 5's (U-SEED-1); the score's scale and query, the duplicate rule, and whether the first idea has an agent of its own, are task 3's (U-SEED-2, A-SEED-2) [ours].
- **Traces.** P-SEED-1 … 4 [§3.1]; P-CFG-2 [App. A.2]; P-CFG-12 [§3.1]; P-ROSTER-3 … 5 [§3.1] [Fig. 4] (image).
- **Why ours.** §3 says ideas are filtered for novelty while §3.1 only sorts (A-SEED-1); we keep §3.1's ranking, and a threshold stays an optional ablation. App. B says the generator does not propose compute scaling, and no inputs are named (U-SEED-3) [§3] [§3.1] [App. B] [ours]. A generator that repeats itself would otherwise loop without bound, or fill the pool with one idea (MISS-20) [ours].
- **Decides.** A-SEED-1; U-SEED-3 [ours].
- **Depends on.** U-SEED-1, task 5; U-SEED-2 and A-SEED-2, task 3 [ours].
- **Test.** Logic, in mock mode, with N_seed = 6 and scripted scores: the pool holds exactly 6 ideas, sorted by score, descending, each with two references, and the lowest-scoring idea is still in it; an idea with an unknown score sorts last; the Idea Generator's recorded input holds G, the limitations and the scored pool; a generator scripted to repeat its first idea stops after 18 attempts with one idea in the pool and the reason recorded [ours].

### R-STG-3 · The baseline, scored once per task at its admission, from its pinned code

- **Requirement.** The baseline stage runs once per task, at its admission and before any run, with the BASE values; its records have the task as their scope, and every run of the task reads them [§3.2] [ours]:
  - **E_base.** The harness fits and scores the task's code at its pinned commit on every search seed of the manifest, as task 6's IR-4 sets it; E_base and its spread across seeds are the records R-RUN-6's noise floor reads, and no agent's code produces them (IR-4.2; U-INT-4) [ours];
  - **C_base.** The Baseline Coding Agent prepares C_base, the copy that ideas start from: the pinned code, unchanged, with the agent's notes on how it runs beside it. C_base's code hash must equal the pinned commit's with its packaging diff, so that E_base's records stand for it (task 6's IR-4.3, IR-14.3); a copy that differs is refused [§3.2] [ours];
  - **The check.** Task 6's sealed check compares the pinned code with the published numbers on the report role, once per baseline key, before admission: a new manifest version that keeps the key reads the report role no second time, and a changed published number is compared with the sealed values already released, which counts as another admission attempt (IR-15.2; U-TOP-5). It is one-sided: a baseline weaker than a published number by more than the manifest's tolerance fails, and a stronger one passes and is recorded. The tolerance is a value of task 5's, set before admission [ours];
  - **On failure.** The task is not admitted, with *baseline not reproduced*. No agent repairs the baseline; a person may repackage the task as a new manifest version, at most k times, k a value of task 5's fixed in the first manifest, with the packaging iterating on the search role only and the roles' index files unchanged after the first sealed-check attempt; every attempt is reported (IR-15.5, IR-15.7) [ours];
  - **Into A_Coder.** A_Coder receives E_base and C_base, a recorded extension of Eq. 2 [§3.2, Eq. 2] [ours].

  Whether the baseline also gets a tuning budget is task 6's (U-SUB-2) [ours].
- **Traces.** P-BASE-1 [§3.2]; P-STATE-5 [§3.2]; P-ROSTER-6 [§3.2].
- **Why ours.** The paper runs the baseline first, on the subset, with no check (U-BASE-2); Figure 5 draws it inside each idea's pipeline (A-BASE-1); and no stage produces the full-set reference that Table 1's full-set critic compares with (A-FULL-1) [§3.2] [Fig. 5] (image) [Tab. 1]. Once per task saves up to 9 coding sessions a run and gives every idea one reference; task 6's second version runs the baseline's fits and its sealed check at admission (IR-4.2, IR-15) [ours]. ⛔ WHY NOT let the agent change C_base: a strengthened copy would pass its gain to every idea, credited to the idea against E_base, as general training controls were in TeCh's case [App. B] [ours]. ⛔ WHY NOT a two-sided check: a stronger baseline makes every gain in the loop harder, never easier, since the loop's gains are against E_base (EI-17) [ours]. Repackaging that may re-carve the report split could select a split on which the baseline reproduces, so the roles stay fixed and the attempts are bounded (the integrity closure, NEW-11) [ours].
- **Decides.** A-BASE-1; U-BASE-2, its branch; A-FULL-1, its first half: who produces the full-set reference [ours].
- **Depends on.** U-INT-4, U-TOP-5 and U-SUB-2, task 6 [ours].
- **Test.** Logic, in mock mode: two runs of one task with three ideas each make one Baseline Coding Agent call and one baseline scoring per search seed, at admission; with the sealed check scripted to pass, round 0 starts and A_Coder's recorded input holds E_base and C_base; scripted to fail, the task is not admitted, with *baseline not reproduced* and no A_Coder call; a repackaging beyond k, or one that changes a role's index file after the first attempt, is refused; a new manifest version that keeps the baseline key reads the report role no second time; one that changes only a published number is compared with the released sealed values, counts as an attempt, and can turn a pass into a refusal [ours]. Enforcement, on the toy task [ours]:
  - a Baseline Coding Agent scripted to strengthen the code it copies, adding a generic training control, is refused, and an idea that does nothing gains nothing; in the twin that accepts the copy, that idea's subset gain grows by the strengthening and it passes the veto [ours];
  - a Baseline Coding Agent scripted to weaken its copy changes no gain, since E_base comes from the pinned code; in the twin that scores the agent's copy as E_base, every gain grows by the weakening [ours].

### R-STG-4 · The idea experiment on the subset

- **Requirement.** The subset experiment runs with the SUB values [§3.2] [ours]:
  - **Veto.** The Subset Critic's `Good` stands only if the rule's subset entry passes over the harness's search-role records of the idea against E_base (R-RUN-6; U-INT-4, U-TOP-5); a `Good` it blocks counts as `Engineer` while the budget lasts, and the record says why [§3.2] [ours];
  - **Switches.** The idea's code declares its mechanism as switches in its configuration, which turn the mechanism off and leave every other change in place; a version that declares none cannot pass the veto. Engine code reads the declarations from the hashed code tree and passes their values as job arguments to the agent's own entry points, never to a scoring item; the values are part of the job's identity, so the control is a row of its own (task 6's IR-2.3, IR-32.1; U-INT-4). Where a switch is declared or changed, its scope is checked against the idea's description, recorded before its code was scored, before any veto or critic reads the result (R-INT-10; A-INT-3); a switch that turns off more than the mechanism is a finding about the code, which only a code change repairs, and its version cannot pass the veto. The check is an LLM's, so its error rates are measured on a planted corpus as IR-31 measures task 6's checks, which task 6 confirmed on 2026-10-02 that it adds to IR-31.1, with bundled and sabotaged switches; an idea whose recorded description itself bundles generic controls passes the check and the floor, and only the critic's rubric, and U-SUB-2's tuned baseline once task 6 adds it, can catch it, by detection only [ours];
  - **Engineering.** The Subset Engineering Agent tunes and repairs code. It never adds, removes or replaces a component of the idea, which only A_FullEng does, in §3.4 and §3.6. The idea's component list is its declared switches; a step that adds, removes or renames one, or changes what one gates, changes the list, and is refused at the component-list check and counted (R-INT-10) [§3.2] [§3.4] [§3.6] [ours];
  - **Scoring.** Each coding or engineering session ends with one scoring by the harness, and agent code cannot ask for one (IR-13) [ours].
- **Traces.** P-SUB-1 … 4 [§3.2]; P-CFG-3 [App. A.2]; P-ROSTER-7 … 9 [§3.2]; P-ROSTER-32 [Fig. 3] (image).
- **Departs from.** P-SUB-2: the critic's `Good` no longer decides alone [§3.2] [ours].
- **Why ours.** The critic's words, substantially inferior or consistently better, have no margin or test (U-SUB-1). The trigger for engineering is tuning or code adjustment, yet the one redesign in the artifacts replaced four components (A-ART-5); and an ablation that cannot turn the mechanism off cannot attribute a gain to it (EI-7) [§3.2] [p. 40] (image) [ours]. A switch its author scopes, checked only at drafting and repaired by rewriting the method, lets TeCh's generic controls pass as the mechanism (the integrity closure, NEW-4) [App. B] [ours].
- **Decides.** U-SUB-1; A-ART-5 [ours].
- **Depends on.** U-INT-4, U-TOP-5 and A-INT-3, task 6: the harness, the role it scores, and who checks a switch's scope [ours].
- **Test.** Logic, in mock mode: a critic scripted as always `Engineer` gives 2 engineer calls, 3 critic calls and `Bad`; a `Good` whose fixture records pass the subset entry sends the idea to the full set; a `Good` whose records fail it leads to engineering, and after the budget to `Bad`, with *margin not met* in the record; a first `Bad` makes no engineer call; an engineer scripted to remove a component is refused, and the refusal is counted; a version that declares no switch cannot pass the veto; a switch whose scope check is scripted to fail blocks the veto before the critic is called, and a revised method text does not lift it [ours].

### R-STG-5 · The idea experiment on the full benchmark

- **Requirement.** The full-set experiment runs with the FULL values: the Full-Set Critic judges the idea against E_base on every full-set setting of the search role, R-STG-3's reference, behind the rule's full-set entry (R-RUN-6; U-INT-4, U-TOP-5), with at most 2 judged engineering refinements; a full-set `Bad` enters the traces as a failed idea. - **Traces.** P-FULL-1 … 3 [§3.2]; P-CFG-14 [App. A.2]; P-ROSTER-10, P-ROSTER-11, P-ROSTER-12 [§3.2]; P-ROSTER-33, P-ROSTER-42 [Fig. 3] (image) [App. A.2].

Judging against the published number would credit an idea with any gap between the paper's machine and ours: in the one trace, 0.41 of a claimed 1.99 points came from a weaker reproduction [p. 41] [p. 42] (image) [ours].
- **Decides.** U-FULL-1; A-FULL-2; A-FULL-1, its second half: the critic's reference [ours].
- **Depends on.** U-INT-4 and U-TOP-5, task 6 [ours].
- **Test.** Logic, in mock mode: a critic scripted as always `Engineer` at full scale gives 2 engineer calls, 3 critic calls, and a trace with `Bad`; the critic's recorded input holds E_base on every full-set setting and no published number; a `Good` whose records fail the full-set entry leads to engineering; a Full-Set Engineer scripted to remove a declared switch is refused, and the refusal is counted [ours].

### R-STG-6 · A_Coder, one call per idea

- **Requirement.** A_Coder runs the subset stage and then, after a subset `Good`, the full-set stage, as one call per idea. It takes G, h, E_base and C_base, and returns the trace tuple (h, E^h, C^h, d^h, r^h), each E^h a record of the harness (U-INT-4) [§3.2, Eq. 2] [ours]. An idea pruned on the subset keeps in its trace at least its verdict and its feedback, the failure log that A_Evolve reads [§3.3]. The trace's further fields, and the unit of work, are task 3's (U-CODER-1, U-CFG-2) [ours].
- **Traces.** P-CODER-1 [§3.2, Eq. 2]; P-ROSTER-13 [§3.2]; P-STATE-6 [§3.2]; P-ROSTER-31 [Fig. 3] (image).
- **Decides.** A-BASE-1, the extended signature [ours].
- **Depends on.** U-CODER-1 and U-CFG-2, task 3; U-INT-4, task 6 [ours].
